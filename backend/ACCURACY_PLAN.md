# 简谱图片识别：精度优化方案

## 结论

当前阶段最适合本项目的不是“整页图片直接生成 JSON”，而是分层混合方案：

1. 页面校正与谱行切分；
2. 高分辨率、小符号检测；
3. 以音符数字为根节点的二维关系图；
4. 受简谱语法和拍号约束的 JSON 解码；
5. 标题、调号、拍号、歌词走独立文字 OCR。

这套方案可解释、容易用少量真实数据纠错，也能在 36GB M3 Pro 上完整训练。
端到端视觉 Transformer 可作为拥有大量真实“谱行图片 → token”配对后的第二阶段实验，
不适合作为当前 2000 张单一渲染风格合成图的主方案。

## 已确认的旧链路问题

- 已训练检测器实际参数是 `imgsz=320, epochs=20, device=cpu`。小圆点和细线在
  320px 输入中会丢失。
- 旧 `data.yaml` 的 train/val 都是同一目录，验证集泄漏，旧 mAP 不能代表泛化。
- 旧拼装器按所有框的 y 坐标分行，会把上加点、数字和减时线拆成三行。
- Transformer 只接收类别序列，不接收框坐标；它无法知道修饰符属于哪个音符。
- Transformer 用完美真值框训练、用带漏检/错检的预测框推理，存在训练/推理域差距。
- 合成集曾有类别完全无样本；修复跨行渐弱标注后，当前 42 类在 train/val 均有样本。
- 单一字体、白底、无透视的合成图与手机照片差异远大于检测模型版本差异。

## 推荐架构

### 第一阶段：页面与谱行

- EXIF 方向、灰度对比度归一化；照片增加四点透视校正。
- 优先按谱行裁剪后识别；当前实现先用 1280px、18% 重叠切片作为无需额外标注的过渡方案。
- 标题、调号、拍号和歌词单独裁剪并使用文字 OCR，不与音乐符号共用一个 42 类检测头。

### 第二阶段：原子符号检测

- 保留 YOLO 小模型作为基线，输入 1280；数字、休止符、小节线和技巧符号使用框检测。
- 对减时线、连音线、渐强/渐弱这类细长符号，后续可增加分割头；它们的端点关系比矩形框类别更重要。
- 先做好真实测试集再比较 YOLOv8s、更新的小模型或分割模型，不能用泄漏的合成验证集选型。

### 第三阶段：关系图与约束解码

- 节点：检测类别、置信度、归一化框坐标和可选 ROI 图像特征。
- 边：`modifier_of`、`next_note`、`barline_of`、`tie_start/end`、`slur_start/end`。
- 第一版使用几何规则；积累关系标注后换成 2-4 层小型 GNN/关系 Transformer。
- 解码时加入约束：升降号只能挂音符；上下点决定八度；减时线决定时值；小节内拍数
  应与拍号一致。低置信度且违反拍数时保留候选，做束搜索而非静默猜测。

## 数据优先级

1. 固定 50-100 张真实图片为测试集，永不训练；按图片来源/曲谱而不是随机框拆分。
2. 标注 300-500 张目标场景真实图片做第一轮微调；每轮收集用户修正结果做主动学习。
3. 合成数据增加多字体、字重、字号、行距、纸张纹理、阴影、模糊、JPEG、透视和局部遮挡。
4. 罕见类别做按类采样，但验证/测试保持真实分布。
5. Transformer/GNN 的输入必须包含检测器真实预测（含漏检和误检），不能只用真值框。

## 正确的评估方式

- 检测：每类 precision/recall、mAP50-95，特别单列圆点、减时线和罕见小节线。
- 关系：`modifier_of` 边的 precision/recall/F1。
- 音符：pitch、octave、duration、accidental 各字段准确率及完整音符准确率。
- 乐谱：token edit distance、measure exact match、整页 exact match。
- 线上返回低置信度字段和候选值，让编辑器突出显示，而不是只返回一个无置信度 JSON。

## 本机训练建议

M3 Pro（18 核 GPU、36GB 统一内存）适合：960-1280px YOLO small、轻量分割模型、
小型 GNN，以及约 100M 参数以内的谱行级 encoder-decoder 实验。检测训练默认参数已经改为
`device=mps, imgsz=960, batch=8, epochs=100`；如果 1280 出现内存压力，把 batch 降到 4，
不要先降低分辨率。

本机实测：当前稳定运行时为 `torch=2.13.0`、`torchvision=0.28.0`、
`ultralytics=8.4.114`。旧 Torch 2.2.2 会在 MPS 的动态标签分配中报张量形状错误。
谱行数据使用 `960/batch=20/rect` 完成 2210 张一轮训练约 4 分钟，峰值约 19.6GB；
日常迭代可用默认 batch=8，最终小符号精调再升到 1280。

修复标注与二维关系后，390 张验证图、11,001 个音符在“使用真值检测框”的
理论上限测试中，音高、完整音符、小节和整页完全匹配率均为 100%。旧生产权重在
5 页抽样上的音高编辑相似度为 97.89%，但完整音符仅 4.95%、小节/整页为 0。
当前生产权重配合互斥语义 NMS，在互斥的 390 页验证集上达到：音高编辑相似度
93.68%、完整音符 88.54%、小节 39.26%、整页完全匹配 8.72%，音符数相似度
99.59%（10956/11001）。相比旧后处理，完整音符和平均小节指标明显提升，但整页
完全匹配仍受小节线类别影响，后续应由拍号约束解码而不是继续放宽全局阈值。
真实扫描页仍需靠人工标注集继续解决字体域差异，不能用合成指标替代。

```bash
cd jianpu-renderer
python3.10 -m venv backend/.venv
source backend/.venv/bin/activate
pip install -r backend/requirements.txt

python backend/scripts/split_dataset.py
python backend/scripts/train_detector.py --device mps --imgsz 960 --batch 8
```

建议先从已有权重做一轮较快的全量微调，再进行 1280 精调：

```bash
python backend/scripts/train_detector.py \
  --model backend/weights/best.pt --device mps \
  --imgsz 960 --batch 8 --epochs 20 \
  --name yolov8s_jianpu_960_v2
```

第一轮新训练只能验证“未见合成谱”的提升。是否真正改善手机照片，必须用独立真实测试集回答。
